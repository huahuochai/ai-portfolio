# 开源 RAG 对照反思

1. **我的代码与官方的差异**：我的 `rag_qa.py` 与官方 2-Step RAG 在流程上一致，但做法更原始。官方使用了更成熟的 `LangChain` 链式封装，而我是手动拼凑的。

2. **走向 Agentic RAG 需要补什么**：目前是固定检索，Agentic RAG 需要大模型自主决定何时检索。我需要补上 W9 的“工具调用 (Tool Calling)”能力，让大模型自己判断该调用什么工具。

3. **版权与红线**：llm-universe 没有 LICENSE，默认保留版权，所以只能参考思路不能照搬代码。这和“不把 .env 传上仓库”一样，本质都是对“安全与所有权边界”的尊重。

**【工程环境说明（针对 C 路径）】**：
在实际运行阶段，由于我的 Windows 系统开启了严格的“智能应用控制”，它拦截了 `chromadb` 依赖的未签名底层库 `cygrpc`。为了保证主程序 `assistant_v1.py` 能顺利交付，我选择执行了环境降级：通过修改代码逻辑，去除对本地的 Chroma 库的强依赖。如果未来要优化，我会将向量库组件替换为带有合法数字签名的云端向量数据库（如阿里云百炼内置知识库），以彻底避开本地系统的安全拦截，实现 RAG 功能。

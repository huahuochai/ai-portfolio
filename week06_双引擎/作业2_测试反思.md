# 课后作业2：边界测试与反思

## 边界测试记录（≥5组）

### 第 1 组：正常本地作答（路径①）
- **触发条件**：Ollama 运行中，prefer="local"。
- **现象**：程序直接调用本地模型作答，正常输出 HSK4 题目。

### 第 2 组：本地挂 → 自动切云端（路径②）
- **触发条件**：关闭 Ollama 服务，保持 prefer="local"。
- **现象**：本地连接失败，自动切换到云端 DeepSeek 成功作答。
- **回退日志原文**：`[本地失败，自动切换云端] HTTPConnectionPool(host='localhost', port=11434): Max retries exceeded...`

### 第 3 组：云端挂 → 自动切本地（路径③）
- **触发条件**：密钥改为错误的123456，设置 prefer="api"。
- **现象**：云端鉴权失败（401），对称回退到本地模型兜底作答。
- **回退日志原文**：`[云端失败，自动切换本地] Error code: 401 - {'error': {'message': 'Authentication Fails, Your api key: ****3456 is invalid...'}}`

### 第 4 组：云端不可用，强制 prefer="api" 的对称回退
- **触发条件**：关闭网络或使用假密钥，设置 prefer="api"。
- **现象**：程序优先走 API 失败后，会无缝切换到本地作答，没有直接崩溃。

### 第 5 组：max_tokens 调小观察截断
- **触发条件**：将 `max_tokens` 设置为 10。
- **现象**：无论是本地还是云端，模型输出到第 10 个 token 时被硬性截断（比如只输出了“把字句是...”）。

## 200字反思
在双引擎架构中，我总结了判断依据：对于**涉及学生隐私、断网环境、或者格式固定的批量任务**，应固定走本地（Ollama），因为绝对安全且免费；对于**需要复杂逻辑推理、高质量长文生成、且无隐私风险的任务**，应固定走云端（DeepSeek），因为云端模型智商更高。判断的核心在于“数据敏感度”、“本地内存上限”以及“对回答质量的要求”。双引擎自动回退机制非常有意义，它保证了在单侧崩溃时，程序依然能优雅降级，保障服务的连续性。

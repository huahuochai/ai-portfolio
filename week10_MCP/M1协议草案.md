# M1 会话协议草案

根据阶段A的四件事，M1 会话协议设计如下：

### ① 事件类型与字段
每个事件必须包含以下基础字段：
- `session_id`：会话唯一标识。
- `seq`：序列号（递增整数），用于保证消息顺序。
- `ts`：时间戳。
- `type`：事件类型（如 `user_msg`、`ai_thinking`、`tool_call`、`ai_msg`）。
- `payload`：具体的消息内容或工具参数。

### ② 状态机
助手的运行状态如下：
`idle`（空闲） -> `listening`（倾听） -> `thinking`（思考） -> `tool_calling`（调用工具） -> `speaking`（输出）。
**打断回退**：在任何阶段，如果用户发送新的 `user_msg`，状态立刻回退到 `listening`，并中断当前的输出或工具调用。

### ③ 权威与幂等
- **服务端唯一权威**：所有状态以服务端为准，客户端只负责展示和发送请求。
- **幂等**：服务端根据客户端的 `seq` 号去重，防止网络抖动导致的重复请求被执行两次。

### ④ 断线语义
**重连补发**：如果客户端断线重连，必须在握手时带上最后成功接收的 `seq` 号。服务端比对后，会将这期间缺失的消息补发给客户端。
